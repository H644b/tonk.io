# Implemented features and parity evidence

The target is independent Bonk.io with its native feature set and full code mods. The pinned original engine, UI, seven modes, map/skin editors, tutorial and resource modules are reused. Independent backend contracts are implemented from the shipped client's requests and runtime evidence. A universal 1: 1 claim would require access to the original private backend and exhaustive input/map/browser coverage, which are unavailable.

Details: `native-differential-parity.json`, `native-xp-settlement-path.json`, `native-replay-fixture.json`, `native-viewport-boundary.json` and current browser acceptance evidence under `evidence/verification/`. See `SERVICE-PARITY.md` for endpoint and administration detail.

Full code mods intentionally have broad game-page access. Client consent is required before first execution of each exact profile; hash verification proves content identity, not that an arbitrary mod is trustworthy. Browser hosts may share client content, while Node server entrypoints require trusted operator installation. Original proprietary material retains its original ownership.


## Publishing preparation

Browser-facing development/self-hosting intros were removed from Help, Workbench, consent, account labels, and errors. Technical modding docs remain. Publishing screenshots and the scoped copy review are under `evidence/verification/publishing/` and `.impeccable/review/publishing-*`.

The suite now has 43 passing tests. Production-only installation and the bundled mod CLI were verified on Node 24.22.1. A real libSQL server (sqld 0.24.32) verified persistence after two complete app-cache wipes, including an abrupt process kill: account, session, map, compiled pack, assets, enabled state, and server mod storage restored. Final targeted storage/proxy checks also pass. The production dependency audit reports zero known vulnerabilities.

`render.yaml` targets Render Free with external Turso/libSQL persistence, so no paid disk is required. Provider quotas and cold starts apply. Docker/Compose/Caddy alternatives are prepared, but the Docker engine and Compose plugin are unavailable here; no container image build or public Render/Turso deployment was verified. See [deployment guide](DEPLOYMENT.md). These checks do not expand the native parity claims above.
