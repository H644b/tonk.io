# Implemented features and parity evidence

The target is Tonk.io, an independent game based on the pinned native client, with its native feature set and full code mods. The pinned original engine, UI, seven modes, map/skin editors, tutorial and resource modules are reused. Independent backend contracts are implemented from the shipped client's requests and runtime evidence. A universal 1: 1 claim would require access to the original private backend and exhaustive input/map/browser coverage, which are unavailable.

## Workers release verification

Workers uses a native Engine.IO WebSocket adapter. Supabase RLS and service-only permissions protect account records; database advisors found no issues. A transactional outbox and revision comparison prevent stale writes, and tests cover rejected-write recovery plus runtime-metadata exclusion. Live checks verified H644b ownership, denied member/cross-origin administration, private map moderation, bot permissions/capacity, account suspensions/unbanning, curator changes, kicks, room closure and audit records.

Bots use heuristic terrain and game-mode decisions. All seven native modes have simulated movement/scoring checks against an idle opponent; rollback snapshots reproduce the same controls/state. Actual browser bots scored rounds. This does not establish optimal play or successful navigation on every community map.

The room host's example pack was compiled in the live browser and relayed through Workers. A fresh peer received Download & Join / Leave Room consent and loaded the same SHA-256 profile, asset and registries. Workers room uploads are limited to 8 MiB compressed/expanded. Trusted server modules must be bundled at deployment and use Workers-supported APIs; arbitrary Node addons and runtime installation of new server JavaScript are not supported.

The prior Node/libSQL persistence and production-only CLI checks remain historical evidence for alternate hosting. The production dependency audit reports zero known vulnerabilities. Docker/Compose/Caddy files are prepared; a container image build remains unverified. Free-plan quotas and active-object duration apply. See [deployment guide](DEPLOYMENT.md). None of these checks certify every native feature, original private service policy, or all possible mods.
